# AnvilTaskManager

Discord-бот для учёта задач клана **Anvil Empires (NG)**: создание и принятие задач, подтверждение выполнения, архив, рейтинг исполнителей, справочник тегов и учёт времени в голосовых каналах.

Стек: Python 3.12, discord.py ≥ 2.5.2, SQLite (WAL), python-dotenv, Docker.

---

## Как поднять бота

### 1. Создать приложение Discord

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications).
2. **New Application** → задайте имя.
3. Вкладка **Bot** → **Reset Token** → скопируйте токен (`DISCORD_TOKEN`).
4. Включите Privileged Gateway Intent при необходимости (для войса достаточно стандартных intents + Voice States — они уже заданы в коде).
5. **OAuth2 → URL Generator**:
   - Scopes: `bot`, `applications.commands`
   - Bot Permissions: как минимум `Send Messages`, `Embed Links`, `Read Message History`, `Connect`/`View Channels` для войса; для админ-функций удобнее `Manage Messages` (удаление сообщений задач).
6. Откройте сгенерированную ссылку и добавьте бота на сервер.

### 2. Узнать ID каналов и пользователей

В Discord: Настройки → Расширенные → **Режим разработчика**.

- ПКМ по серверу → **Копировать ID сервера** → `GUILD`
- ПКМ по каналу задач → **Копировать ID** → `TASKS_CHANNEL_ID`
- ПКМ по каналу логов → **Копировать ID** → `LOG_CHANNEL_ID`
- ПКМ по пользователю → **Копировать ID** → в `ALLOWED_USERS` (через запятую)

### 3. Клонировать и настроить окружение

```bash
git clone <url-репозитория>
cd AnvilTaskManager
cp .env.example .env
```

Заполните `.env`:

```env
DISCORD_TOKEN=ваш_токен
GUILD=id_сервера
ALLOWED_USERS=id1,id2
LOG_CHANNEL_ID=id_канала_логов
TASKS_CHANNEL_ID=id_канала_задач
```

| Переменная | Обязательно | Назначение |
|------------|-------------|------------|
| `DISCORD_TOKEN` | да | Токен бота |
| `GUILD` | рекомендуется | ID гильдии; slash-команды синкаются сразу на сервер. Если `0` — глобальный sync (до часа) |
| `ALLOWED_USERS` | нет | Доп. админы по Discord ID |
| `LOG_CHANNEL_ID` | нет | Канал событий (создание, принятие, подтверждение…). `0` — без логов в Discord |
| `TASKS_CHANNEL_ID` | рекомендуется | Канал доски задач. Если `0` — пост в канал, где вызвали `/add` |

### 4. Запуск локально

Нужен Python 3.12+.

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
python main.py
```

При старте создаются каталоги `data/`, `logs/` и БД `data/tasks.db`. В консоли должно появиться: `Бот <имя> запущен!`

### 5. Запуск через Docker

```bash
docker compose up -d --build
```

- тома: `./data` и `./logs` монтируются в контейнер;
- логи процесса: `logs/output.log`, `logs/errors.log`;
- перезапуск: `unless-stopped`.

Остановка:

```bash
docker compose down
```

### 6. Проверка

1. В Discord введите `/ping` — ответ `Pong!`.
2. `/add` — создайте тестовую задачу, убедитесь что сообщение появилось в канале задач.
3. С другого аккаунта нажмите **Принять** → **Завершить** → с авторского **Подтвердить**.
4. `/rating` — исполнитель должен появиться в рейтинге.

Если slash-команд нет: проверьте `GUILD`, перезапустите бота, подождите несколько секунд (для глобального sync — дольше).

## Концепция

Бот ведёт доску задач в Discord. Участник создаёт задачу (`/add`), другой участник принимает её кнопкой на сообщении, выполняет и отправляет на подтверждение. Автор (или администратор) подтверждает работу — задача уходит в архив, а исполнитель получает +1 в рейтинге.

### Жизненный цикл задачи

```
open → in_progress → pending_approval → completed
         ↑                │
         └──── return ────┘
```

| Статус | Название | Что происходит |
|--------|----------|----------------|
| `open` | Открыта | Ждёт исполнителя. Кнопки: **Принять**, **Удалить** |
| `in_progress` | В работе | Взята исполнителем. Кнопки: **Завершить**, **Отказаться**, **Удалить** |
| `pending_approval` | Ожидает подтверждения | Автор/админ проверяет результат. Кнопки: **Подтвердить**, **Вернуть**, **Удалить** |
| `completed` | Завершена | В архиве. Сообщение в канале удаляется |

Правила:

- Автор **не может** принять свою задачу.
- Завершить / отказаться может только исполнитель.
- Подтвердить / вернуть может автор или администратор.
- Удалить может автор или администратор.

### Статистика участников

| Счётчик | Когда растёт |
|---------|--------------|
| `created_tasks` | Пользователь создал задачу |
| `resolved_tasks` | Пользователь выполнил задачу (её подтвердили) |
| `closed_tasks` | Пользователь как автор подтвердил чужую задачу |

`/rating` показывает топ исполнителей по `resolved_tasks`.

### Голосовой учёт

Бот считает время в голосовых каналах гильдии:

- время начисляется только если участник **не** в `self_deaf` (`self_mute` не мешает);
- накопленное время хранится в `voice_totals`;
- завершённые сессии — в `voice_sessions` (хранятся 14 дней);
- flush в БД раз в 60 секунд и при выходе из войса.

### Теги

Файл `data/tags.json` — справочник подсказок по игре/клану. Команда `/tag` показывает описание; файл можно править без рестарта бота.

## Структура таблиц

База: `./data/tasks.db` (SQLite, режим WAL).

### `tasks`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | TEXT PK | Короткий id задачи (8 hex-символов) |
| `description` | TEXT | Описание |
| `status` | TEXT | `open` / `in_progress` / `pending_approval` / `completed` |
| `author_id` | TEXT | Discord ID автора |
| `author_name` | TEXT | Имя автора на момент создания |
| `executor_id` | TEXT | Discord ID исполнителя (nullable) |
| `executor_name` | TEXT | Имя исполнителя (nullable) |
| `created_at` | TIMESTAMP | Создание |
| `taken_at` | TIMESTAMP | Принятие в работу |
| `completed_at` | TIMESTAMP | Подтверждение |
| `cancel_comment` | TEXT | Комментарий (legacy / служебное) |
| `channel_id` | TEXT | Канал сообщения задачи |
| `message_id` | TEXT | ID сообщения с кнопками |
| `guild_id` | TEXT | ID гильдии (для ссылок на сообщение) |

Индексы: `status`, `executor_id`.

### `participants`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `user_id` | TEXT PK | Discord ID |
| `user_name` | TEXT | Имя |
| `created_tasks` | INTEGER | Создано задач |
| `closed_tasks` | INTEGER | Закрыто как автор |
| `resolved_tasks` | INTEGER | Выполнено как исполнитель |
| `points` | INTEGER | Legacy, не используется |

### `voice_totals`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `user_id` | TEXT PK | Discord ID |
| `user_name` | TEXT | Имя |
| `total_seconds` | INTEGER | Накопленное время в войсе (секунды) |

### `voice_sessions`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | INTEGER PK | Автоинкремент |
| `user_id` | TEXT | Discord ID |
| `user_name` | TEXT | Имя |
| `channel_id` | TEXT | Голосовой канал |
| `channel_name` | TEXT | Название канала |
| `started_at` | TEXT | Начало сессии (ISO) |
| `ended_at` | TEXT | Конец сессии (ISO) |
| `duration_seconds` | INTEGER | Длительность |

Индексы: `ended_at`, `user_id`. Старые сессии чистятся раз в час (retention 14 дней).

## Команды

| Команда | Кто может | Описание |
|---------|-----------|----------|
| `/add` | Все | Создать задачу (модальное окно с описанием). Сообщение публикуется в `TASKS_CHANNEL_ID` или в текущий канал |
| `/list` | Все | Список активных задач с пагинацией |
| `/rating` | Все | Рейтинг исполнителей по числу подтверждённых выполнений |
| `/menu` | Админы | Админ-меню: список, архив, удаление задачи, очистка данных |
| `/tag <tag> [user]` | Все | Справка по тегу из `data/tags.json`. Без `user` — только вам; с `user` — публично + mention |
| `/ping` | Все | Проверка ответа бота (`Pong!`) |

### Кнопки на сообщении задачи

| Кнопка | Статус | Кто | Действие |
|--------|--------|-----|----------|
| Принять | open | Не автор | Взять задачу в работу |
| Завершить | in_progress | Исполнитель | Отправить на подтверждение (+ комментарий) |
| Отказаться | in_progress | Исполнитель | Вернуть задачу в open |
| Подтвердить | pending_approval | Автор / админ | Завершить, начислить статистику, убрать сообщение |
| Вернуть | pending_approval | Автор / админ | Вернуть в работу (+ комментарий) |
| Удалить | active | Автор / админ | Удалить задачу и сообщение |

### Админ-меню (`/menu`)

- **Список задач** — активные задачи
- **Архив** — завершённые задачи
- **Удалить задачу** — выбор из списка
- **Очистка** — необратимое удаление:
  - статистика участников (`participants`);
  - активные задачи (`open` / `in_progress` / `pending_approval`) + их сообщения;
  - архив (`completed`)

### Кто считается администратором

1. ID из `ALLOWED_USERS` в `.env`, **или**
2. право Discord `Administrator` / `Manage Server` на сервере.

## Администрирование

### Повседневная работа

1. Участники создают задачи через `/add`.
2. Исполнители берут задачи кнопками на сообщениях в канале задач.
3. Автор подтверждает работу — задача уходит в архив (`/menu` → **Архив**).
4. Рейтинг смотрят через `/rating`.

### Теги (`data/tags.json`)

Формат — JSON-массив:

```json
[
  {
    "name": "wiki",
    "description": "https://anvilempires.wiki.gg/"
  }
]
```

После сохранения файла бот подхватит изменения сам (кэш по mtime), рестарт не нужен.

### Очистка данных

`/menu` → **Очистка** (только админы). Действие необратимо, требуется подтверждение в модальном окне.

| Тип | Что удаляется |
|-----|----------------|
| Статистика | Все строки `participants` (рейтинг обнулится) |
| Активные задачи | Записи и сообщения Discord по активным статусам |
| Архив | Все `completed` задачи |

Голосовые таблицы очисткой из меню **не** затрагиваются.

### Логи

| Место | Содержимое |
|-------|------------|
| `logs/` | Ротируемые файловые логи приложения |
| Канал `LOG_CHANNEL_ID` | События по задачам в Discord |
| Docker: `logs/output.log`, `logs/errors.log` | stdout/stderr контейнера |

### Бэкап

Скопируйте `data/tasks.db` (и при необходимости `data/tags.json`) при остановленном боте или после короткой паузы — это вся персистентность задач, статистики и войса.

### Права бота на сервере

Убедитесь, что бот видит каналы задач и логов и может:

- писать сообщения и embeds;
- читать историю;
- удалять **свои** сообщения задач (после подтверждения / очистки);
